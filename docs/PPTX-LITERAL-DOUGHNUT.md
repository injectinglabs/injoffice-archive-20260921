# Source literal doughnut preview

`NativeOpaqueChart.literalDoughnut` carries a qualified `literal-doughnut-v1` source record: explicit `firstSliceAngle`, `holeSize`, positive integer literal `values`, and effective indexed RGB `colors`. One record cannot carry both pie and doughnut profiles. The native source chart remains preserve-only; the projection does not authorize chart mutation.

Enable `literalDoughnutPreview: true` when calling `compileNativePptxSlide`, or call `createNativeLiteralDoughnutPaths(record, cx, cy)` for standalone vectors. The playground's source chart checkbox previews both supported families. The option defaults off and is independent of `literalPiePreview`; the existing packaged image fallback remains available.

Qualification requires one source doughnut series, explicit holeSize10..90, explicit angle0..360, varyColors=false, contiguous1..64 positive integer literals up to1e9, transparent chart/plot backgrounds and complete local series/point RGB/no-line paint. Sparse point overrides bind by source index. Missing hole size, additional rings, caches/formulas, labels, legends, explosion, effects or unmodeled markup refuse this profile. Existing pie source qualification is unchanged; a shared qualified decoder examines the original family element without rewriting XML.

Geometry is an explicitly disclosed host policy: a circle centered inside the frame, inner radius equal to the source hole percentage of outer radius, clockwise sectors starting from up, chords spanning at most two degrees, and one final rounding to integer EMU. It does not reproduce Office plot layout. Each source point stays one contiguous fill path, with the outer arc followed by the reverse inner arc; this retains full-circle holes without artificial antialias seams between fragments. Exact cardinal angles and the wrapped terminal angle share coordinates even for odd frames. A frame too small to retain a one-EMU inner radius or ring thickness refuses vector preview and keeps fallback behavior. The standalone helper throws RangeError for such geometry.

The renderer path budget is now512 commands, explicitly increased from256 because a full annular path needs363 commands at the existing angular resolution. Canvas, SVG and recording consumers iterate path commands and have no separate256 limit. Existing coordinate/node/depth limits remain unchanged; every source point consumes a render node. With n≤64, total annular commands are bounded by2∑ceil(180·value/total)+3n <360+5n≤680. No general custom-path contract is added. Tests exercise full-ring and skewed[999,1] source values through the actual compiler, source point/node budgets, and rejection of513 generated commands.

Source basis: [ECMA-376](https://ecma-international.org/publications-and-standards/standards/ecma-376/) Part1 sections21.2.2.50,21.2.2.82 and21.2.2.172 (pie-series source content), plus [Microsoft's hole-size definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.charts.holesize?view=openxml-3.0.1). Generated source/WASM/browser evidence verifies qualification, annular pixels, default-off behavior and source preservation; it is not independent Office fidelity qualification.

This milestone does not complete the chart engine: richer doughnuts/pies, category/value/date axes, bar/line/scatter and other families, workbook data and cache provenance, labels/legend/theme cascade, combinations,3D and chart extensions remain tracked in the external orchestration completion matrix.
