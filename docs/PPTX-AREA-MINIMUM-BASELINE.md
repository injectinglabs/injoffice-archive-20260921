# Source minimum closure for literal area

Previously accepted area sources required category `crosses=min`, but extraction discarded that token and the renderer closed every band at zero. The optional closed `sourceBaseline: {crossing: 'min', value: string}` now preserves the exact token and numeric minimum lexeme on newly extracted area records. Go and TypeScript require the value to match `yAxis.min` exactly; forged values/tokens/extra fields fail. Legacy caller-provided records without the descriptor retain their zero-baseline policy.

The correction changes closure alone: each standard series closes to the source minimum; only the first stacked or percentage band's lower boundary changes. Cumulative tops, later lower boundaries, source values, XML series sequence and original index/order metadata remain unchanged. The horizontal stroke uses that same minimum. Existing area out-ticks use the same source edge, including the already accepted scale ending at zero. Supplied-font low/high label placement remains the existing measured-margin policy.

The retained Office 16.112.4 baseline corpus independently establishes the minimum closure. In page 1, standard values `[4,-2,3,-1]` on `[-10,10]` retain identical original/Office chart semantics: the final -1 series closes to -10, whereas the previous implementation closed it to zero. The original 30-case baseline source hash is `49804a74bdbd9d966eaf94bcd1f8cf815173afdfd5c45037e4556c5b2a8b8ede`; its PDF hash is `7d6a05fd0b0a15f26a7e5f7a1948d1b046e04636bd4034b55287bf464958e227`. Nine separate axis-isolation cases distinguish category-controlled horizontal closure from value-axis crossing. Existing source/saved/PDF files and their proof manifests under `pptx-stacked-office-20260913` are unchanged; no new Office automation is performed.

This slice does not admit negative stacked/percentage values, `autoZero`/`max` category crossings, nonzero value-axis crossings or workbook area. It does not import the frozen signed topology/contact-stitching preparation. Existing rational, input, category, generic path and 1,536 area-command limits are unchanged.

Permanent tests generate 20 actual strict/transitional source packages spanning standard, nonnegative stacking/percentage, negative-minimum zero totals, zero minimum, reversal, supplied-font labels/ticks, grouped frames and a 256-category boundary case. Five negative source packages retain exact opaque charts for autoZero/max, negative stacks/percentages and duplicate crossings. Actual Go/WASM source fields and hashes are compared; production framed-worker output matches direct compilation without changing the source deck. Separate renderer tests prove legacy zero behavior and unchanged later stack bands.

For the alternating large fixture, 256 values `-1,+1,...` clipped to `[-.5,.5]` with minimum closure produce 128 visible trapezoids: four vertices and a close each, exactly 640 commands in one compound fill. The previous zero closure produced 1,280 commands. Worker and browser assertions use the new exact 640 expectation, while the runtime ceiling stays 1,536. This specific count is not a universal output-bound proof.

The dedicated browser workflow runs the actual source helper, worker and production SVG painter. It checks exact data-path geometry/paint identities, excludes glyph subtrees from area evidence, verifies zero-minimum emptiness and negative-minimum zero-series fill, captures the fully visible SVG region, and measures pixel differences after hiding only area fills. All control visibility is restored before failure evidence. Actual browser success and artifact inspection remain remote CI gates; local syntax and source/worker tests do not imply a browser pass.
