# Embedded CFF form fonts

The existing caller-font option accepts fixed OpenType CFF1 faces, standalone or selected from a collection. No new appearance mode is needed. HarfBuzz shapes the original OpenType face; the saved PDF embeds its complete CFF outline program and uses the existing positioned Unicode appearances. TrueType embedding remains unchanged.

Name-keyed CFF1 programs receive a CID wrapper with an identity GID-to-CID charset and one font dictionary. The original charstrings, hint data, private dictionaries and local subroutines remain byte-for-byte in a relocated payload; new absolute pointers refer into that payload. Original private-relative local-subroutine offsets stay valid. Existing CID-keyed CFF1 programs keep their original bytes, charset, ROS and font dictionaries, including nonmatching GID/CID values and multiple dictionaries. No fontkit subset output is used in production.

The PDF descendant is CIDFontType0 with a FontFile3 stream of subtype CIDFontType0C containing raw CID-keyed CFF, never an SFNT wrapper. It has no CIDToGIDMap. A custom Encoding CMap maps source-semantic character codes to actual font CIDs; ToUnicode maps those character codes to the exact source spans. Widths are keyed by font CID. Distinct strings that shape to the same glyph retain separate source codes, including canonical equivalents. `/V` and ActualText retain the original text. Generic reader spacing, bidi and normalization behavior remains separate from canonical form values, as described in the [Unicode policy](PDF-UNICODE-SHAPING.md).

Preflight validates CFF1 headers, bounded monotonic INDEX offsets (262,144 total entries across unique INDEX structures), supported DICT operators and arities, existing SIDs, charset and encoding membership, FD selection, private/subroutine ranges and structure overlaps. Only exact sharing between private dictionaries or between subroutine INDEXes is accepted. Every glyph’s reachable Type 2 program is checked with bounded execution: 48 operands, 10 nested subroutine calls, 96 hints and five million total operations. Invalid stack accesses, undefined hint sequencing, truncated masks and programs, invalid negative stem widths and name-keyed endchar composites refuse before form changes.

This profile requires the Top FontMatrix to match the OpenType units per em and any FD FontMatrix to be identity. Synthetic/stroked fonts, non-Type2 programs, embedded PostScript, random computational behavior, deprecated unsupported operators, CFF2 and variable/color fonts explicitly refuse. These are font-technology qualifications, not a script whitelist. The existing 16 MiB source and resulting-program bounds apply; full programs can be larger than a text-specific subset. Continuation glyphs still use exact outlines without rasterizer hinting, while primary text glyphs retain CFF hints.

Fixtures include a pinned OFL name-keyed Noto Devanagari OTF and a reproducibly generated small CID-keyed Japanese font retaining eight font dictionaries and sparse CIDs. The generator uses the already-installed subset-font tool only for test fixture creation; source hashes, tool versions, WASM hash, command and licenses accompany the fixture. Regenerate offline with `node scripts/generate-pdf-cff-fixture.mjs /path/to/pinned/NotoSansJP-Regular.otf --check`. No external corpus is downloaded in CI.

Primary format authorities are Adobe [CFF specification 5176](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5176.CFF.pdf), [Type 2 specification 5177](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5177.Type2.pdf), the [OpenType CFF table](https://learn.microsoft.com/en-us/typography/opentype/spec/cff), and [PDF 32000-1](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/PDF32000_2008.pdf), sections 9.6–9.10.

The PDF adapter normalizes FDSelect only inside its fresh, exclusively owned fontkit1.1.1 parser using the independently validated source GID-to-FD mapping. This avoids a format3 range-boundary binary-search defect that can select the preceding dictionary and wrong local subroutines. No font bytes, shared prototypes or module state are changed; the saved CFF program and source CID mapping stay intact. The regression includes neighboring base/variation glyphs and checks every range boundary against the validated source mapping.

Distinct source strings that share a CFF CID use separate Type0 views with injective Encoding and exact per-view ToUnicode maps. The views share one descendant font and embedded CFF stream; stable mappings refresh as later fields introduce aliases. Appearance text selects the appropriate view explicitly. This avoids PDF.js dropping nonfirst code-to-CID aliases while preserving exact source semantics and independent-reader rendering. The operation permits at most256 views and65535 semantic codes, refusing before output if exceeded.
